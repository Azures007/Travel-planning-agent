# 高德地图 API 集成说明

## 概述

成功集成高德地图 API 用于地理编码，显著提升国内地点定位的准确性。

## 问题背景

之前使用 OpenStreetMap Nominatim API 进行地理编码，存在以下问题：
1. **精度低**：国内地点定位不准确，误差可达数公里
2. **同名地点歧义**：例如"灵源山"会定位到安徽省而非晋江
3. **速度慢**：需要严格的速率限制，每次查询间隔1秒以上

## 解决方案

### 1. 高德地图 API 集成

使用高德地图的地理编码 API（`/v3/geocode/geo`），优势：
- **国内精度高**：POI 数据准确，误差通常在 10-50 米
- **速度快**：速率限制宽松，支持更高并发
- **免费额度充足**：每天 30 万次调用额度

### 2. 同名地点歧义解决

**策略**：在查询时将城市名和地点名组合
```python
# 组合查询：城市+地点
address = f"{city}{location}"  # 例如："晋江灵源山"
params = {
    'key': AMAP_KEY,
    'address': address,
    'city': city
}
```

**效果对比**：
- 错误：`address="灵源山", city="晋江"` → 返回安徽省池州市 [29.15, 117.53]
- 正确：`address="晋江灵源山", city="晋江"` → 返回福建省晋江市 [24.75, 118.52]

### 3. 测试结果

**晋江景点测试**（5/5 成功）：
```
✓ 五店市传统街区  [24.8179, 118.5788]
✓ 安平桥         [24.7073, 118.4481]
✓ 灵源山         [24.7470, 118.5210]
✓ 梧林传统村落    [24.7550, 118.6028]
✓ 晋江万达广场    [24.8187, 118.5726]
```

所有坐标均在晋江范围内（纬度 24.6-25.0，经度 118.3-118.8）。

## 技术实现

### API 端点

`POST /api/geocode/batch`

**请求**：
```json
{
  "locations": ["五店市传统街区", "安平桥"],
  "destination": "晋江"
}
```

**响应**：
```json
[
  {
    "location": "五店市传统街区",
    "lat": 24.81787,
    "lon": 118.578767,
    "display_name": "福建省泉州市晋江市五店市传统街区",
    "cached": false,
    "approximate": false
  }
]
```

### 代码位置

- **简化版本**（当前使用）：`app/api/geocode_simple.py`
  - 纯高德 API，无缓存
  - 适合快速迭代和调试
  
- **完整版本**（待优化）：`app/api/geocode.py`


## 已知问题与改进方向

### 1. 缓存功能暂时禁用

**原因**：同步的 SQLite 操作在异步上下文中会阻塞事件循环（特别是 Windows + `WindowsSelectorEventLoopPolicy`）。

**解决方案**：
- 使用 `asyncio.to_thread` 将同步数据库操作放到线程池
- 或改用异步数据库驱动（如 `aiosqlite`）

### 2. 错误处理

当前实现对 API 失败直接返回空结果，可以改进为：
- 记录失败原因
- 提供更详细的错误信息给前端

### 3. 批量查询优化

当前是串行查询，可以优化为：
- 真正的并发请求（去掉不必要的延迟）
- 使用 `asyncio.gather` 并发处理多个地点
